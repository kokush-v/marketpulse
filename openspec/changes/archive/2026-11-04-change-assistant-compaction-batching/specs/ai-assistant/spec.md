## MODIFIED Requirements

### Requirement: Compact Long Conversation Context

The system SHALL keep as the conversation context the user and assistant messages recorded after the last compaction. When the user sends a message and the conversation context including that message exceeds the configured context message or character limit, the system SHALL compact all context messages except the latest user and assistant exchange into a persisted conversation summary generated by the assistant model, and SHALL keep the latest exchange in the context. The system SHALL NOT compact while the context stays within the limits. The summary SHALL prioritize the coins the user interacted with and SHALL also retain user-stated facts and preferences, decisions made in the conversation, and open questions. Each model request SHALL include the conversation summary when one exists together with the conversation context. Original messages SHALL remain in conversation history.

#### Scenario: Conversation fits the limits

- **Given** an authenticated user's conversation context including the new message is within the context limits
- **When** the user sends a message
- **Then** no compaction is performed
- **And** the model receives the summary, if any, and all context messages

#### Scenario: Conversation exceeds the limits

- **Given** an authenticated user's conversation context including the new message exceeds the context message or character limit
- **When** the user sends a message
- **Then** the system summarizes all context messages before the latest user and assistant exchange into the conversation summary before the assistant responds
- **And** the model receives the summary, the latest exchange, and the new message
- **And** the full message history remains visible to the user

#### Scenario: User continues after a compaction

- **Given** an authenticated user's conversation was just compacted
- **When** the user sends the next message and the context is within the limits
- **Then** no compaction is performed

#### Scenario: User refers to a coin from early in the conversation

- **Given** an authenticated user discussed SOL early in a conversation that has since been compacted
- **When** the user asks "show me the latest news for it"
- **Then** the assistant requests news for SOL

#### Scenario: Summary contains old prices

- **Given** the conversation summary mentions a price discussed earlier
- **When** the user asks for the current price of that coin
- **Then** the assistant obtains current data through its tools instead of reusing the summarized price

### Requirement: Keep Open Confirmations In Context

The system SHALL include the current non-expired pending confirmation of a conversation in every model request for that conversation, even when the message that proposed it has been compacted. Expired, confirmed, or cancelled actions SHALL NOT be included.

#### Scenario: Proposal message was compacted

- **Given** an authenticated user has a pending alert deletion proposal whose message has been compacted
- **When** the user asks what is waiting for confirmation
- **Then** the assistant describes the pending alert deletion

#### Scenario: Proposal expired

- **Given** a pending proposal in the conversation has expired
- **When** the user sends a message
- **Then** the expired proposal is not presented to the model as pending
